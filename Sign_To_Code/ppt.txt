## Architecture (concise)

1) Camera (OpenCV) captures frames → 2) MediaPipe Hands extracts 21 landmarks → 3) Feature extractor computes normalized features (angles, distances, ratios / or raw normalized coordinates) → 4) Classifier (RandomForest or small NN) returns class + confidence → 5) Command executor applies confidence threshold & cooldown → 6) UI displays feedback and injects keyboard events (pyautogui)

Notes:

- Keep pipeline modular so model or feature steps can be swapped during hackathon (RF → quick to train; NN → more accurate if time allows).
- Use normalized landmark coordinates (relative to hand bounding box) for invariance to distance and camera resolution.

---

## Minimal Data & Modeling Plan (fast, hackathon-friendly)

Data:

- Collect 30s–60s per gesture from 2–4 people (diverse angles/lighting) during hackathon; aim for 300–1000 frame samples per gesture.
- Save landmarks + meta (frame timestamp, handness, bounding box).

Features (two quick options):

- Option A (fast, interpretable): engineered features — finger angles, pairwise distances, normalized coordinates → 50–100 features → RandomForest baseline (fast training)
- Option B (if time permits): small MLP on flattened normalized coordinates or 1D-CNN on temporal windows to capture micro-movements

Training & Validation:

- Split by recording/session (not frame) to avoid overfitting to a single person or position (e.g., 80/20)
- Use cross-validation ideally across participants
- Aim for precision/recall per-class >= 0.9; report confusion matrix and per-class support

Quick hyperparameters:

- RandomForest: n_estimators=200, max_depth=None, random_state=42
- MLP: 2 hidden layers (128, 64), relu, softmax output, early stopping

Evaluation Metrics:

- Accuracy, per-class precision/recall, false positive rate, average inference latency (ms)

## Engineering Contract (2–4 bullets)

- Inputs: single webcam feed (640x480+), per-frame landmarks from MediaPipe
- Output: keyboard events injected to the OS/IDE and a UI state containing (gesture, confidence, timestamp)
- Error modes: no-hand-detected (no action), low-confidence (no action), camera disconnected (UI error state)
- Success: gesture command executed only when confidence >= threshold and cooldown state allows

---

## Edge Cases & Mitigations

- Multiple hands in frame: filter to the primary hand (closest / first detected)
- Lighting changes: normalize coordinates and encourage users to use front-lit setup; add simple brightness check and prompt
- False positives: use cooldown (0.8–1.2s) and require stable prediction for N consecutive frames (N=3)
- Background motion: add simple temporal smoothing on landmarks

- Performance: script that measures average inference latency over 500 frames

## Data Procurement

Purpose: provide a compact, action-ready plan for collecting, labeling, storing, and validating gesture data during the 36‑hour hackathon.

1) Goals & success metrics
- Train a robust 5-class gesture classifier (fist, palm, thumbs-up, peace, pointing).
- Hackathon targets: per-class accuracy ≥ 0.90 on held-out participants; average inference latency <200 ms.

2) Data types to collect
- Primary: MediaPipe hand landmarks per frame (21 landmarks × (x,y,z)), handedness, and bounding box.
- Optional: short RGB clips for debugging and demo (store sparingly, with consent).
- Metadata: participant_id, session_id, gesture_label, fps, resolution, lighting note, timestamp.

3) Minimal quantities (practical)
- Minimum: ~300 frames/gesture across 2–4 participants (≈1,500 frames total).
- Target if time allows: 500–1,000 frames/gesture across 4–6 participants.

4) Collection protocol (fast, repeatable)
- Resolution: 640×480, stable camera. Use a simple capture UI to label sessions in real time.
- Session flow: countdown (3..2..1), record 20–60s per gesture with small orientation/distance variations.
- Perform multiple short sessions (easier to diversify) rather than a single long take.

5) Labeling & storage schema
- Save per-frame JSONL records with keys: participant_id, session_id, frame_idx, timestamp, gesture, handedness, landmarks, bbox, mp_confidence.
- Organize files: data/raw/participant_{id}/session_{id}/landmarks.jsonl (+ optional video.mp4).
- Maintain a manifest.csv summarizing session counts and metadata.

6) Preprocessing & features (quick options)
- Normalize landmarks per frame: translate by wrist origin, scale by hand size (bounding box or landmark distance), optionally rotate to canonical orientation.
- Feature choices: (A) engineered: angles and pairwise normalized distances (~50–100 features) for RandomForest; (B) raw: flattened normalized coords (63 values) for a small MLP.
- Temporal smoothing / stability: require N consecutive identical predictions (N=3) or use short-window majority voting.

7) Augmentation (light-touch)
- Coordinate jitter, small rotations/scales, brightness variation for optional RGB samples. Avoid flips that change semantics unless gesture-invariant.

8) Train/validation/test split strategy
- Split by session/participant (not by frame). Suggested: 70% train / 15% val / 15% test with at least one held-out participant in test to measure generalization.

9) Quality checks & validation
- Per-session: ensure minimum frames, average MediaPipe confidence >0.5, no corrupt records.
- Global: class balance report, confusion matrix after baseline training, and spot-check sample frames/videos.
- Automate checks: scripts that output counts.csv, avg_confidence.csv, and flag low-quality sessions.

10) Privacy & consent
- Prefer landmarks over raw video to reduce PII exposure. If saving video, get explicit consent and store it separately with limited access.
- Use participant IDs only; do not store names/emails in raw data.

11) Tools & quick commands (Windows PowerShell)
```powershell
python -m venv .venv; .\.venv\Scripts\Activate.ps1
pip install mediapipe opencv-python numpy pandas pysimplegui tqdm
```
- Capture: OpenCV + MediaPipe; lightweight UI in PySimpleGUI or Tkinter for labeling during capture.
- Save landmarks as gzipped JSONL for compactness if needed.

- [ ] Implement minimal capture UI that labels and writes per-frame landmarks to JSONL.
- [ ] Collect ≥300 frames/gesture from ≥2 people (aim for 4 if time allows).
- [ ] Train RandomForest on engineered features; validate on held-out participant.
